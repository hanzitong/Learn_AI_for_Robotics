# 第13章　Vision-Language-Action（VLA）モデル

**大規模 VLM の世界知識をロボット行動に「接地」することで，言語指示への汎化を実現する**

---

## 純粋なロボット学習データだけでは，常識的推論と汎化が困難である

ロボット操作に必要な能力と，VLM が既に持つ能力：

| 必要な能力 | VLM による解決 |
|-----------|-------------|
| 物体の性質・用途の理解 | インターネット規模の世界知識 |
| 空間的推論（「左」「上」） | CLIP・SigLIP の空間表現 |
| 多様な言語指示の解釈 | 大規模 LLM の言語理解 |
| 常識的な取り扱い方 | 人間のテキストから暗黙的に学習 |

VLM の事前学習は，ロボット学習だけでは到底得られない知識を転移する

---

## VLA は「ビジョンエンコーダ・LLM バックボーン・行動デコーダ」の3要素で構成される

1. **ビジョンエンコーダ：** カメラ画像 $I_t$ → トークン列 $z_v$（ViT / CLIP ViT）
2. **言語エンコーダ / LLM バックボーン：** テキスト指示 $l$ を処理し，視覚・行動トークンと統合
3. **行動デコーダ：** 視覚・言語コンテキスト → 行動 $a_t$（またはチャンク $a_{t:t+H}$）

この3要素の組み合わせ方（特に行動デコーダの設計）が，VLA アーキテクチャの本質的な差異を生む

---

## RT-2 は行動を「テキストトークン」として表現し，VLM をそのまま行動生成に流用する

**核心的アイデア：** デルタエンドエフェクタ制御（7次元）を 256 ビンで量子化 → 既存語彙トークンとして扱う

$$p(a_{1:K} \mid I_t, l) = \prod_{k=1}^{K} p_\theta(a_k \mid I_t, l, a_{1:k-1})$$

- ロボット操作データとウェブデータを**共同学習（co-training）**
- **結果：** 未見の物体・「ピクニックに必要なものを取って」のような推論タスクへの汎化

---

## OpenVLA は 7B パラメータのオープンソース VLA であり，LoRA で少量データに適応できる

**アーキテクチャ：**
- ビジョンエンコーダ：DINOv2（ViT-L）+ SigLIP ViT-L（連結）
- LLM：Llama 2（7B），プロジェクタ：線形 MLP
- 行動：256 ビン均一量子化

**強み：** 100〜1000 デモの少量データでも LoRA でタスク適応可能

**課題：**
- 推論速度 ≈ 6 Hz → 実時間制御（25〜50 Hz）には不足
- 量子化による行動品質の限界

---

## π0 はフローマッチングを行動デコーダに採用し，連続行動の高品質な生成を実現する

**設計思想：** VLM はコンテキスト理解を担い，行動生成はフローマッチングに分離

$$\mathcal{L}_{\pi_0} = \mathbb{E}_{t, a^0, \varepsilon}\!\left[\|v_\theta(a^k, k, z_{\mathrm{context}}) - (a^0 - \varepsilon)\|^2\right]$$

- **PaliGemma**（SigLIP + Gemma）でテキスト・マルチカメラ画像・ロボット状態を処理
- 行動チャンク $H = 50 \sim 100$ ステップを DDIM 加速サンプリング（5〜10 ステップ）で生成
- **50 Hz の実時間制御が可能**

---

## 自己回帰トークンと拡散デコーダには根本的なトレードオフがある

| 設計軸 | 自己回帰トークン（RT-2，OpenVLA） | 拡散/フロー（π0） |
|--------|-------------------------------|----------------|
| 行動品質 | 量子化誤差が残る | 連続値で高品質 |
| 推論速度 | トークン数に比例して低速 | デノイジングステップ数で調整 |
| 多峰性 | 困難（温度サンプリングで部分対処） | 自然に対応 |
| LLM との統合 | 同一語彙で完全統一 | 別モジュールが必要 |

---

## 複数フレームの視覚履歴なしには，多くのロボットタスクで状態が特定できない

ほとんどのタスクはマルコフ性を持たない → 時間コンテキストが不可欠

| 手法 | 内容 | 特徴 |
|------|------|------|
| フレームスタッキング | 過去 $k$ フレームを ViT に入力 | RT-2 が使用（$k=6$） |
| 行動コンディショニング | 過去の行動列をコンテキストに追加 | 一貫性の向上 |
| Transformer のコンテキスト長 | 全フレームをトークン列として処理 | 最も一般的；GPU メモリが律速 |

---

## まとめ：VLA 設計の要点

| 概念 | 内容 |
|------|------|
| VLA の動機 | VLM の世界知識・推論能力をロボット行動に接地 |
| RT-2 | 行動のテキストトークン化；VLM の共同学習で汎化 |
| OpenVLA | オープンソース；256 ビン量子化＋LoRA アダプテーション |
| π0 | フローマッチングで連続行動を高品質生成；50 Hz 制御 |
| AR vs 拡散 | 品質・速度・多峰性・LLM 統合のトレードオフ |
| 時間コンテキスト | マルコフ性のないタスクには複数フレームが必須 |
