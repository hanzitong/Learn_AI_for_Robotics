# 第13章　Vision-Language-Action（VLA）モデル

## 概要

**Vision-Language-Action（VLA）モデル**は，視覚・言語・行動の三つのモダリティを統合し，自然言語による指示と視覚観測から具体的なロボット行動系列を直接生成するモデルである．VLA は大規模なインターネットデータで事前学習された VLM（第11章）の豊富な視覚・言語表現を，ロボット行動に「接地（ground）」することで，自然言語でのゴール指定・新しい物体への汎化・常識的推論を可能にする．本章では，VLA の設計原理，代表的なモデル（RT-2，OpenVLA，π0），訓練パイプライン，および推論時の行動生成について詳述する．

---

## 13.1　VLA の動機と設計原理

### 13.1.1　なぜ VLM をロボットに使うか

大規模 VLM（第11章）が持つ能力：
- **世界知識：** 物体の性質・機能・色・用途の理解（「リンゴは食べられる」「包丁は刃物だ」など）
- **空間的推論：** 「コップの左」「机の上」などの空間関係の理解
- **指示の解釈：** 多様な自然言語表現の理解と行動への対応付け
- **共通感覚：** 「壊れやすいものは丁寧に扱う」などの暗黙的な知識

これらは純粋なロボット学習データからのみ学習することは困難であり，大規模なインターネットデータからの転移が本質的に重要である．

### 13.1.2　VLA アーキテクチャの三つの要素

すべての VLA モデルは以下の三つの要素を持つ：

1. **ビジョンエンコーダ：** カメラ画像 $I_t$ をトークン列 $z_v$ に変換（ViT / CLIP ViT など）
2. **言語エンコーダ / LLM バックボーン：** テキスト指示 $l$ を処理し，視覚・行動トークンと統合
3. **行動デコーダ：** 視覚・言語コンテキストから行動 $a_t$（またはチャンク $a_{t:t+H}$）を生成

これらの要素の組み合わせ方・学習方法・行動表現によって，異なる VLA のアーキテクチャが生まれる．

## 13.2　RT-2：VLM から VLA へ

### 13.2.1　RT-2 の設計

**RT-2（Robotics Transformer 2）**（Brohan et al., 2023）は，VLM（PaLI-X または PaLM-E）をロボット行動生成に直接適用した最初の大規模 VLA の一つ：

**核心的アイデア：** ロボット行動を「テキストトークン」として表現し，VLM をそのままファインチューニングする：

- 各行動次元（**デルタエンドエフェクタ制御**：x,y,z 位置差分3次元 + roll,pitch,yaw 姿勢差分3次元 + グリッパー開閉1次元 = 7次元）を 256 個の離散ビンで量子化
- ビン ID を既存の語彙外の特殊トークン（例：語彙末尾のトークン）として割り当て
- 行動トークンはテキストと同じ自己回帰デコーディングで生成：

$$p(a_{1:K} \mid I_t, l) = \prod_{k=1}^{K} p_\theta(a_k \mid I_t, l, a_{1:k-1})$$

**訓練：** ロボット操作データとウェブデータ（テキスト・画像キャプション）を**共同学習（co-training）**することで，言語・視覚能力を保持しながら行動生成を学習．

**結果：** RT-2 は新しい物体（訓練時に未見の組み合わせ）や，推論（「ピクニックに必要なものを取って」）を要求するタスクへの強い汎化を示した．

### 13.2.2　RT-2-X と Open X-Embodiment

**Open X-Embodiment**（Open X-Embodiment Collaboration, 2024）は，22 の研究機関・15 種類以上のロボット形態から 100 万以上のデモンストレーションを集めたデータセット（第14章で詳述）．**RT-2-X** はこのデータで学習したモデルで，異なるロボット形態間の汎化能力を示した．

## 13.3　OpenVLA：オープンソース VLA

### 13.3.1　OpenVLA の設計

**OpenVLA**（Kim et al., 2024）は，完全にオープンソースの VLA であり，ロボット学習コミュニティに公開された基準モデル：

アーキテクチャ：
- ビジョンエンコーダ：DINOv2（ViT-L）+ SigLIP ViT-L（2つのエンコーダを連結）
- LLM：Llama 2（7B パラメータ）
- 視覚・言語プロジェクタ：線形 MLP（LLaVA 設計）

行動表現：
- 各行動次元を 256 ビンで均一量子化
- 行動トークンを最初の 256 個の一般的なトークン（最低頻度の 256 語彙）に割り当て（特殊トークン追加なし）

訓練データ：Open X-Embodiment データセット（約 100 万デモンストレーション）

**LoRA によるファインチューニング：** OpenVLA を特定のロボット・タスクにアダプトする際，LoRA（第7章）を用いることで少量データ（100〜1000 デモ）でも高い成功率が達成できることが示された．

### 13.3.2　OpenVLA の課題

- **推論速度：** 7B パラメータの LLM による自己回帰デコーディングは低速（〜6 Hz）；実時間制御（25〜50 Hz）には不足
- **行動品質の限界：** 単純な量子化では細密な操作が困難
- **コンテキスト長：** 長い操作タスク（多ステップ）への対応が課題

## 13.4　π0（パイゼロ）：フロー matching + VLM

### 13.4.1　π0 の設計思想

**π0（pi-zero）**（Black et al., 2024）は，Physical Intelligence（π）が提案した VLA で，高品質な行動生成のために **VLM + フローマッチング拡散（Flow Matching）**を統合する：

**核心的アイデア：** VLM が視覚・言語のコンテキストを理解し，その条件のもとで**行動系列をフローマッチングで生成**する：

- 言語指示・画像（複数カメラ）・ロボット状態を PaliGemma（SigLIP + Gemma）で処理
- 行動系列 $a_{t:t+H}$ をフローマッチングで生成（連続行動，量子化なし）

**なぜ拡散/フロー matching か：**
- 行動の多峰性（同一状態に複数の有効行動がある）を自然に表現
- 連続行動空間での高品質な生成
- VLM の自己回帰トークン生成と分離することで，両者の役割を明確化

### 13.4.2　π0 の訓練パイプライン

**2段階の事前学習：**

**Stage 1（ウェブデータ事前学習）：** VLM バックボーン（PaliGemma）を言語・視覚タスクでインターネットデータにより事前学習（VLM として標準的な方法）

**Stage 2（ロボットデータ事前学習）：** ロボット操作データ（複数のタスク・ロボット形態）でフローマッチング行動ヘッドを含む全体を学習：

$$\mathcal{L}_{\pi_0} = \mathbb{E}_{t, a^0, \varepsilon}\left[\|v_\theta(a^k, k, z_{\mathrm{context}}) - (a^0 - \varepsilon)\|^2\right]$$

（$z_{\mathrm{context}}$：VLM のコンテキスト特徴，$a^k$：ノイズ付き行動，$k$：拡散ステップ）

**Stage 3（タスク固有ファインチューニング）：** 特定タスクのデモデータでファインチューニング

### 13.4.3　π0 の推論

行動チャンク $H = 50 \sim 100$ ステップを一度に生成し，**DDIM 加速サンプリング**（$K = 5 \sim 10$ ステップ）で高速化：

- 推論周波数：50 Hz（チャンク50ステップを1秒以内に生成）
- 実時間制御が可能

## 13.5　VLA 設計の重要な選択

### 13.5.1　アーキテクチャ設計の次元

VLA の設計空間における主要な選択：

| 設計軸 | 選択肢 | 代表例 |
|--------|--------|--------|
| 言語バックボーン | 7B LLM，2B VLM | OpenVLA（7B），π0（3B） |
| 行動デコーダ | 自己回帰トークン，拡散 | RT-2（AR），π0（Flow） |
| 行動表現 | 量子化トークン，連続値 | RT-2（256ビン），π0（連続） |
| 視覚入力 | 1カメラ，多カメラ | OpenVLA（1），π0（3+ カメラ） |
| 行動チャンク | 単ステップ，多ステップ | RT-2（1），π0（50〜100） |

### 13.5.2　自己回帰 vs 拡散デコーダのトレードオフ

| | 自己回帰トークン | 拡散/フロー |
|-|----------------|------------|
| 行動品質 | 量子化誤差が残る | 連続値で高品質 |
| 推論速度 | トークン数が多いと低速 | デノイジングステップ数で調整 |
| 多峰性 | 困難（温度サンプリングで部分的対処） | 自然に対応 |
| LLM との統合 | 完全に統一（同一 vocab） | 別モジュールが必要 |

### 13.5.3　時間的コンテキストの設計

ほとんどのロボットタスクはマルコフ性を持たない（単一フレームでは状態が特定できない）ため，VLA は**複数フレームの視覚履歴**を利用する設計が一般的：

- **フレームスタッキング：** 過去 $k$ フレームの画像を連結して ViT に入力（RT-2 は $k = 6$ フレーム）
- **行動コンディショニング：** 過去の行動系列 $a_{t-H:t-1}$ をコンテキストとして追加
- **RNN 状態：** 隠れ状態で時系列情報を圧縮（計算コスト削減だが表現力の限界）
- **Transformer のコンテキスト長：** 全フレームをトークン列として処理（最も一般的；GPU メモリが律速）

時間的コンテキストの長さと推論レイテンシのトレードオフは，実機制御システムの設計で重要な考慮点である．

### 13.5.4　VLA の評価指標

VLA の実機評価に使われる主な指標：

- **タスク成功率（Task Success Rate）：** 定義されたタスク（物体をPickして特定の場所にPlace等）の完了率
- **部分達成スコア（Partial Credit）：** 完全完了でなくても部分的な達成を評価
- **汎化指標：** 新しい物体・色・指示・環境への成功率

## 13.6　現在の課題と展望

### 13.6.1　VLA の現在の限界

1. **長期依存・多ステップ計画：** 数十手順にわたるタスク（料理，片付けなど）への対応が困難
2. **接触・力覚制御：** 視覚だけでは力フィードバックを要するタスク（ネジ締め，布の操作）が困難
3. **閉ループ速度：** LLM による生成は低速；高速な連続制御（特にダイナミクスが重要なタスク）に課題
4. **分布外汎化：** 訓練データから大きく外れた環境（照明，カメラ位置の変化等）での性能低下

### 13.6.2　展望

- **思考を含む VLA：** Long CoT（Chain-of-Thought）をロボット計画に適用（「このタスクはAをBの前に行う必要がある...」）
- **多感覚統合：** 力覚・触覚・音声センサの統合
- **VLA + RL：** 事前学習済み VLA を出発点としてロボット固有のタスクを強化学習で改善
